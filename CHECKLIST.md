# Приёмка v4 (сначала тестовый бот)

- Сборщик должен завершиться без ошибок. Проверить python -m py_compile bot.py.
- Запуск на копии v3 БД: профили, услуги, расписания, записи и права сохранены. Повторный запуск миграции успешен.
- Два клиента одновременно бронируют пересекающееся время: только один успех. Проверить 90 минут при шаге 30.
- MAX_ACTIVE_BOOKINGS=1: первая клиентская запись проходит, вторая блокируется; перенос существующей проходит. Ручная запись работает.
- Отозвать права: бывший мастер не получает служебные данные о новых отменах/переносах/подтверждениях; личные клиентские сообщения получает.
- Подготовить старые служебные кнопки до отзыва, нажать после: доступ закрыт. Проверить роль управляющего.
- Ручная запись: создать ссылку, клиент запросит привязку, мастер проверит личность, подтвердит. Запись появится у клиента.
- До одобрения ссылка не показывает имя/телефон. Отклонение не выдаёт доступ. Новая ссылка аннулирует старую. Истёкшая ссылка не работает.
- Два запроса на одну ссылку: после первого одобрения второй не может привязаться. Отмена записи до одобрения блокирует привязку.
- Поиск: Антон/антон/АНТОН; телефон со скобками и без; 8 и +7 для 11 цифр.
- История не показывает будущие активные визиты; отменённые будущие видны. Поиск охватывает все периоды.
- Настройки названия/контакта сохраняются после перезапуска.
- CSV получает только управляющий после подтверждения; личный JSON не раскрывает чужих клиентов мастеру.
- Запрос удаления не отменяет визиты. Обезличивание сохраняет действующие записи, очищает контакты завершённых, не позволяет использовать старые ссылки.
- Проверить статус review_required и ручную процедуру обработки остальных мест хранения.
- Напоминания: клиент заблокировал бота — управляющий получает предупреждение. Временная ошибка повторяется. Не отправлять тесты реальным клиентам.
- Проверить логи без токенов/персональных данных; журнал событий содержит ID и операции.
- В группе бот не выдаёт данные. Частые нажатия ограничиваются, после паузы работа возобновляется.
- Проверить резервную копию, восстановление, постоянный диск при обновлении GitHub.


## Приёмка портфолио
- На тестовой копии запустить миграцию дважды: старые записи/услуги/график сохранены, таблица v4_portfolio существует.
- Мастер загружает фото, фото с подписью; документ и подпись длиннее 500 символов отклоняются.
- Готово, Назад, Отмена, Главное меню и /start выходят из загрузки.
- Повтор фото не добавляется; лимит 30 соблюдается. Загрузка после удаления работает.
- Клиент открывает портфолио из списка мастеров и из выбора услуги; листает, выбирает мастера, завершает запись.
- Просмотр не сбрасывает manual/mid/sid и введённые контакты. Проверить возврат во время выбора даты и ввода имени.
- Пустое портфолио показывает понятное сообщение.
- Другой мастер и клиент не могут загрузить/удалить чужие фото даже подделанной callback_data.
- Удаление требует подтверждения; повтор подтверждения безопасен.
- Управляющий удаляет фото активного и отключённого мастера; другие функции его карточки сохранены.
- Отзыв прав во время загрузки/подтверждения удаления закрывает доступ. Старые публичные кнопки отключённого мастера не показывают фото.
- Перезапуск сохраняет фото в каталоге; на другом токене загрузить отдельные тестовые фото.
- Недоступный file_id не блокирует навигацию; на тестовой БД проверить обработку ошибки.
- Повторить полный CHECKLIST v4: запись, перенос, контакты, права, привязки, напоминания, экспорт и backups.
