# CRM салона v4 — обновление присланной версии v3

## Сборка и установка
Положите build_salon_v4.py рядом с вашим актуальным bot.py v3 и запустите python build_salon_v4.py. Сборщик не изменяет исходный bot.py и БД, создаёт папку salon_bot_v4_portfolio и ZIP с файлами в корне. Нужен Python 3.10+.

Перед рабочим обновлением остановите бота и сделайте внешнюю резервную копию базы. Проверьте постоянный диск хостинга. Сначала разверните проект на тестовом боте с отдельным токеном, отдельным MANAGER_ID и копией БД. Не запускайте копию с рабочим токеном.

Загрузка в GitHub: содержимое salon_bot_v4_portfolio, без баз/секретов. Установка pip install -r requirements.txt. Запуск python bot.py. Сохраните прежние BOT_TOKEN, MANAGER_ID, DB_PATH и BACKUP_DIR. Миграция добавляет v4-таблицы без удаления старых данных. Архив не содержит базы.

Новые обработчики добавлены к существующей архитектуре, чтобы сохранить старые функции. Сборщик проверяет ожидаемые участки исходника и синтаксис результата. Это НЕ интеграционное тестирование. Работа Telegram и миграция в вашем окружении здесь не выполнялись.

## Изменения
1. Кнопка «Изменить данные клиента».
2. Служебные отправки мастеру проверяют актуальные права, в том числе перед повторными попытками. Личные клиентские уведомления отозванному мастеру сохраняются. Сообщение, уже переданное Telegram до отзыва, отозвать гарантированно нельзя.
3. Ручная запись: «Ссылка для клиента». Ссылка содержит случайный токен; БД хранит SHA-256. Срок по умолчанию 24 часа. Новая ссылка аннулирует предыдущую. После перехода клиент подтверждает запрос, затем мастер этой записи или управляющий проверяет личность и подтверждает привязку. До одобрения ссылка не раскрывает детали записи. Подтверждение атомарно; возможна только одна привязка. Нельзя считать имя Telegram доказательством личности: свяжитесь по заранее известному контакту. После привязки доступны личные записи и будущие напоминания. Если до визита менее суток, отдельное суточное напоминание пропускается.
4. Поиск имён через Unicode casefold с ё/е; телефоны очищаются от оформления, 8XXXXXXXXXX приводится к 7XXXXXXXXXX. Поиск по части номера поддерживается, страна не угадывается для других номеров.
5. История показывает завершённые и отменённые записи; предстоящие отдельно. В карточке мастера раздел «Записи» сохраняет общий список. Поиск охватывает все периоды.
6. Настройки салона доступны управляющему: название и контакт администратора. Можно задать SALON_NAME, ADMIN_CONTACT в окружении; настройки в БД имеют приоритет. Значения отображаются клиенту в меню.
7. Журнал действий: транзакционные события создания/переноса, общие мутации, изменения записи, прав, выгрузки и привязки. Журнал предназначен для поддержки, не является защищённым от администратора сервера юридическим аудитом. В нём нет значений телефонов/имён или токенов; есть Telegram ID, время и ID объектов. Некоторые события представлены общей операцией над таблицей, а не подробным сравнением полей.
8. MAX_ACTIVE_BOOKINGS — максимум активных предстоящих записей на Telegram-клиента, по умолчанию 5. Проверка в транзакции при создании; ручные записи и переносы не считаются новыми. Привязка уже созданной вручную записи может превысить лимит: она не создаёт новый визит. Ограничение частоты входящих сообщений/кнопок: RATE_LIMIT_COUNT=20 за RATE_LIMIT_SECONDS=10 на пользователя в одном процессе. Не является защитой от распределённых атак. Только личные чаты.
9. Управляющий получает уведомление о недоставке напоминания: сразу при постоянной ошибке или отсутствии привязки, либо после трёх неудачных проходов с временной ошибкой. Если самому управляющему нельзя доставить сообщение, бот продолжает пытаться. Редкие повторы при сбое между отправкой и отметкой в БД возможны.
10. Клиентская выгрузка JSON: связанные личные записи, собственный профиль мастера/услуги и запросы удаления; не включает записи чужих клиентов. Управляющий может получить CSV всех записей после подтверждения. CSV защищён от интерпретации строк как формул. Выгрузки отправляются в Telegram и сами требуют защиты/срока хранения. Не включают полную копию всех внутренних таблиц.
11. Запрос удаления от клиента регистрируется и рассматривается управляющим. Завершённые/отменённые записи можно обезличить после отдельного подтверждения; действующие записи сохраняются. Для непривязанных записей доступен запрос удаления контактов из карточки. Это НЕ полное автоматическое исполнение юридического запроса: профиль мастера, логи, резервные копии, Telegram-сообщения и другие места хранения рассматриваются отдельно. Запрос переводится в review_required и требует внешнего завершения администратором; интерфейс отметки полного исполнения не добавлен. Нельзя сообщать клиенту о полном удалении без проверки. При восстановлении старой резервной копии нужно повторно применить обезличивание.

## Известные эксплуатационные ограничения
- Один салон, один процесс бота. Нужна SQLite 3.35+.
- FSM в памяти: незавершённые формы сбрасываются при перезапуске. Подтверждённые записи, ссылки, запросы и настройки сохраняются.
- Локальные резервные копии не заменяют внешние. Копии before_start не очищаются автоматически.
- При недоступности сервера уведомления задерживаются; SLA и мониторинг хостинга настраиваются отдельно.
- Напоминания — за сутки; дополнительное за 2 часа не добавлено. Предоплата, акции, лист ожидания и MAX не входят в это обновление.
- Статус «Пришёл/Не пришёл», календарь, права, расписание и остальные функции v3 сохранены.
- PRIVACY_TEXT должен содержать актуальную политику и контакты. Не собирайте реальные данные до настройки хранения, доступа и документов.

## Откат
Остановите приложение, верните код v3 и при необходимости БД из внешней копии. v3 не знает лимиты, ссылки и правила уведомлений v4. Изменения между копией и откатом требуют отдельного переноса. Не делайте откат вслепую после новых реальных записей.


## Портфолио мастера
Собрано дополнительным сборщиком build_salon_v4_portfolio.py из исходного bot.py v3 и прежнего build_salon_v4.py. Результат: salon_bot_v4_portfolio_portfolio/ и salon_bot_v4_portfolio_portfolio.zip. Все дополнения прежнего сборщика v4 включаются в результат.

Мастер: Кабинет мастера → Моё портфолио → Добавить фото. Отправляйте фото обычным сообщением Telegram, не документом. Подпись необязательна, до 500 символов. После фото можно отправить следующее; Готово завершает загрузку. Не отправляйте большие серии: действует прежнее ограничение частоты сообщений. Лимит — 30 фото на мастера. Новые фото показываются первыми, просмотр по одному с кнопками. Повтор той же фотографии определяется по Telegram file_unique_id. Изменение подписи: удалить фото и загрузить заново.

Клиент: под именем каждого доступного для записи мастера есть «Портфолио мастера». Кнопка также появляется после выбора мастера, рядом с предложением посмотреть работы. Просмотр не сбрасывает текущую форму записи. «Вернуться к записи» возвращает к выбору мастера/услуги, а если ввод записи уже начат — предлагает продолжить по прежним сообщениям без потери данных. «Выбрать этого мастера» открывает выбор его услуг.

Управляющий: Управление салоном → Мастера → карточка → Портфолио мастера. Может просмотреть и удалить фото после подтверждения, в том числе у отключённого мастера. Загрузка разрешена только действующему владельцу портфолио. Отозванный мастер не может управлять фото, клиенты не могут просматривать его портфолио по старым кнопкам. Уже доставленные сообщения отозвать таким способом нельзя. Восстановление прав возвращает доступ к сохранённым работам.

Хранение: таблица v4_portfolio в прежней SQLite, существующие записи не удаляются. Хранятся Telegram file_id/file_unique_id, подпись, ID мастера и время. Сами изображения остаются в Telegram; резервная копия SQLite НЕ содержит оригиналы фотографий. file_id предназначен для этого бота и обычно не подходит другому боту с другим токеном. Оригиналы работ храните отдельно. Для проверки на другом тестовом боте загрузите новые тестовые фотографии. При ошибке отправки фото доступны навигация и удаление.

Удаление убирает работу из каталога, но не удаляет автоматически Telegram-сообщения, копии у получателей или backups. Портфолио и подписи нужно отдельно учитывать при обработке запросов удаления/выгрузки: прежняя личная JSON-выгрузка v4 их не включает. Загружайте только фотографии, на публикацию которых имеются необходимые права и согласия. Портфолио не является обязательным условием готовности мастера к записи.

Это Telegram-обновление. MAX и ВКонтакте здесь не подключены.
Сборщик проверяет структуру исходников и синтаксис результата при запуске; интеграционные тесты, Telegram и миграция здесь не запускались. Рабочий деплой — только после внешней копии базы и подтверждения постоянного хранилища VERF.
