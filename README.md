# Журнал салона — полный проект версии 2.0

## Для нового запуска
Python 3.10+; один постоянно работающий процесс (worker, не веб-сайт).
Установка: pip install -r requirements.txt
Запуск: python bot.py
На хостинге задайте BOT_TOKEN и числовой MANAGER_ID. Если ID неизвестен, временно поставьте 1, запустите /id в боте, исправьте переменную и перезапустите.
.env.example — пример, не активные настройки. Для локального запуска скопируйте его в .env.

## Существующая база — ВАЖНО
Остановите старый бот, скачайте резервную копию базы и при наличии WAL/SHM. Не загружайте пустую базу поверх существующей. В этом архиве базы и токена нет.
Сохраните прежний DB_PATH. База должна находиться на постоянном диске хостинга. Не указывайте произвольный путь, которого нет на хостинге. Обновление кода само по себе не делает диск постоянным.
При первом запуске версия 2 делает SQLite backup перед миграцией, добавляет столбцы и таблицы, переносит график из исходной версии. Данные мастеров, услуг и записей не удаляются. Поддержан также импорт timetable_v2/blocks_v2 от предыдущего обновляющего скрипта, если эти таблицы присутствуют.
Перед применением к рабочей базе проверьте миграцию на её отдельной копии с тестовым ботом. Для отката восстановите исходную копию БД и прежний код — старый код не знает нового графика.

## Что есть
- Один управляющий, несколько мастеров, клиенты.
- Профили, услуги с длительностью и необязательной ценой.
- График кнопками: дни недели, отдельные даты, несколько рабочих интервалов в день, выходные. Перерыв — промежуток между рабочими интервалами. Время можно выбрать с шагом 30 минут или ввести ЧЧ:ММ вручную.
- Шаг начала записей 5/10/15/20/30/60 минут; старые значения шага сохраняются при миграции.
- Закрытие личного времени без фиктивных клиентов, повторное открытие интервала.
- Автоматический расчёт окон, транзакционная защита от пересечения записей.
- Клиент: имя, телефон, подтверждение, отмена, перенос, «Мои записи».
- Мастер и управляющий могут переносить записи. Перенос сохраняет мастера, услугу, исходные цену и длительность, включая скрытую из каталога услугу. Старое окно освобождается только после успешного переноса.
- Статусы «Ожидается», «Пришёл», «Не пришёл», «Отменён». Отметки посещения доступны сотруднику с момента начала визита; можно исправить ошибочную отметку.
- «Приду» подтверждает визит; отсутствие подтверждения не отменяет бронь. Перенос сбрасывает подтверждение.
- Напоминание за сутки; для записи менее чем за сутки дополнительного напоминания нет. После простоя возможна поздняя доставка, если визит ещё не начался.
- Просмотр сегодня, завтра, 7 дней, 30 дней, все предстоящие. Отменённые записи видны сотрудникам в выборках по периоду. 30 дней — не календарный месяц.
- Понятные ошибки BOT_TOKEN/MANAGER_ID, повторы при временной недоступности Telegram, корректное закрытие сессии.
- Копии SQLite при запуске и каждые 24 часа; последние 14 ежедневных копий. Копии перед запуском автоматически не удаляются: следите за диском.

## Ограничения и эксплуатация
Код подготовлен, но не исполнен и не проверен здесь с реальным Telegram/хостингом. Обязательно выполните CHECKLIST.md.
Ручные записи не привязываются к Telegram клиента и не получают клиентских уведомлений. Мастер должен связаться с клиентом самостоятельно. По одному телефону бот не может написать человеку.
Ночные смены, копирование графика на несколько дней, список ожидания, онлайн-оплата, веб-панель, экспорт, отзыв прав и антиспам не включены в этот пакет.
Формы настройки профиля/услуг остаются текстовыми. Настройка графика — кнопками, дата вводится текстом.
Существующие записи при изменении графика/закрытии времени НЕ отменяются; бот предупреждает о конфликте. Граница шага начала не считается конфликтом старой записи.
Незавершённые диалоги хранятся в памяти; после перезапуска начните через /start. Несколько копий одного бота не запускайте.
Общие уведомления повторяются до трёх попыток, но не имеют постоянной очереди. Для напоминаний временные ошибки повторяются следующим циклом. В редком случае сбоя после отправки до отметки в БД возможно повторное сообщение. Доставка не гарантируется, особенно при блокировке бота пользователем.
Подтверждение «Приду» в старом сообщении после переноса не принимается. Отмена требует повторного подтверждения и проверяет время записи.
Нужно постоянное хранилище и отдельная внешняя копия: если резервные копии находятся на том же временном диске, удаление диска уничтожит их вместе с базой. Логи показывают путь, но код не способен проверить условия сохранности диска у провайдера.
Файл базы и копии содержат персональные данные без шифрования. Ограничьте доступ к серверу/копиям. Не публикуйте базу и .env. До реального запуска задайте собственный PRIVACY_TEXT, правовое основание/необходимое согласие, сроки хранения, контакт ответственного и порядок удаления. Автоматическое удаление данных не реализовано.
Телефон проверяется по формату, не по владению. Используйте только личные чаты с ботом для работы с данными клиентов.

## Первичная настройка
Управляющий выдаёт мастеру доступ по /id. Мастер: /start → Кабинет мастера → Профиль, Услуги, Расписание.
Профиль: Анна | Мастер маникюра
Услуга: Маникюр | 90 | 1500
Без цены: Консультация | 30 | -
Клиент открывает /start → Записаться.
