# CRM салона — обновление интерфейса v3

## Установка
Сборщик использует приложенный вами bot.py версии 2 как основу. Он не изменяет исходный файл и базу. В архив входят полный bot.py с дополнениями, зависимости, .env.example, .gitignore, README.md и CHECKLIST.md.

Перед обновлением остановите бота и сохраните внешнюю резервную копию базы. В GitHub загружайте содержимое папки salon_bot_v3 (не сам сборщик). Сохраните текущие BOT_TOKEN, MANAGER_ID, DB_PATH. Команда установки: pip install -r requirements.txt. Команда запуска: python bot.py. Один процесс, Python 3.10+, SQLite 3.35+.

При запуске прежний initialize создаёт резервную копию и выполняет миграцию v2; затем добавляется masters.enabled. Существующие мастера получают enabled=1. Записи, услуги, расписание не удаляются. Старые имена таблиц и полей сохраняются. Для отката к v2 нужно восстановить копию БД и старый код: v2 не учитывает отозванные права.

## Новые возможности
- Заголовок «CRM Салона» для управляющего/активного мастера; «Запись к мастеру» для клиента. Клиентские функции сохранены всем.
- Постоянная нижняя клавиатура: Главное меню, Назад, Отмена. Telegram может позволить вручную свернуть её. Навигация отменяет несохранённый ввод, а не сохранённые записи.
- Пошаговые профиль и услуги с подтверждением. Для редактирования услуги повторно вводятся все три поля.
- Управляющий: список мастеров, карточка, готовность, ближайшая запись, записи, просмотр графика, ручная запись, отзыв/восстановление прав.
- Отзыв прав скрывает мастера из нового бронирования и закрывает служебные действия; история и предстоящие записи остаются. Личные клиентские записи доступны. Уведомления уже существующих записей могут по-прежнему приходить бывшему мастеру — это отдельная политика уведомлений, не доступ к кабинету.
- Календарь месяца для бронирования с отметками выходных/занятости; ручной ввод дат сохранён. Календарь проверяет доступность, но финальная защита от двойной записи остаётся в транзакции при подтверждении.
- Карточка записи: длительность, статус, подтверждение; служебное редактирование имени/телефона, повторная ручная запись с сохранёнными контактами.
- История (включая будущие и отменённые записи) с постраничным выводом. Поиск по подстроке имени/телефона: кириллица зависит от регистра, телефон ищется в сохранённом формате. Мастер видит только собственных клиентов, управляющий — всех.
- Подтверждение закрытия времени, удаления интервала, выходного, сброса графика, открытия закрытого времени и скрытия услуги. Предупреждения показывают потенциально затронутые записи; они не отменяются автоматически.
- Публикация мастера для клиентского бронирования после заполнения имени, добавления активной услуги и непустого актуального графика.

## Ограничения и безопасность
Это исходный код обновления, не прошедший здесь выполнение с Telegram API. Сборщик проверяет синтаксис через ast.parse, но это не интеграционное тестирование. Сначала проверьте на отдельном тестовом боте с копией базы.

Главное меню и Отмена доступны во всех формах; Назад возвращает на предыдущий шаг там, где он реализован, либо в соответствующий раздел. Меню Telegram может быть свернуто клиентом. Даты изменения графика по-прежнему вводятся текстом, календарь добавлен к бронированию.

Просмотр расписания мастера управляющим — только чтение. Редактирование по-прежнему выполняет мастер. Карточка повторной записи использует текущую активную услугу и цену, создаёт ручную запись без Telegram-привязки. Подтверждение/уведомления такого клиента не отправляются. Смена телефона не меняет Telegram ID.

Требуется постоянный диск на хостинге. База и локальные резервные копии на временном диске могут исчезнуть при деплое. Ежедневные копии сохраняются предыдущим механизмом; внешние копии и проверка восстановления — ответственность владельца. Копии before_start не очищаются автоматически: следите за диском.

Не публикуйте .env, базы, резервные копии или контакты в GitHub. Настройте PRIVACY_TEXT с реальной политикой и контактом салона. Текущая версия не заменяет юридическое оформление обработки данных.
